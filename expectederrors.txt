## Quick crawler response

When a crawler receives a 500:

1. Record the URL, timestamp, status, response headers, and response body.
2. Retry only a limited number of times with exponential backoff.
3. Respect `Retry-After` if it is provided.
4. Reduce concurrency for that domain.
5. Check whether the error affects one URL, one path, one region, or the entire site.
6. Compare responses using different user agents and IP locations.
7. If you control the site, inspect application, web-server, CDN, database, and load-balancer logs.

A 500 generally indicates a **server-side problem**, not that the crawler itself is necessarily broken; however, crawler traffic can expose or amplify issues such as rate limits, overloaded endpoints, cache misses, and untested URL patterns. [developer.mozilla](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/500)
